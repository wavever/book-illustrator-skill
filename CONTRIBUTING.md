# Contributing

Thanks for helping. Bug reports with a minimal reproduction (a tiny synthetic EPUB/HTML/Markdown file is ideal) are the most useful thing you can send.

## Setup and tests

From the repository root:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r skills/book-illustrator/requirements.txt
.venv/bin/python -m unittest discover -s tests -t . -v
```

- Tests are offline: books are generated by `tests/native_fixtures.py` and `tests/conversion_helpers.py`, network calls are mocked, and Chrome/Java are replaced by small stub scripts where needed.
- Optional checks run only when the tool is present and are skipped otherwise:
  - Calibre `ebook-convert` (found via `$CALIBRE_CONVERT`, `PATH`, or the default install paths);
  - Java plus an epubcheck 5.1.0 jar (`$EPUBCHECK_JAR`, or the cache `epubcheck_diff.py` fills under `~/.cache/book-illustrator/`).

## Ground rules

- **Never commit books or personal material.** No real EPUB/MOBI/PDF files, extracted book text, candidate image folders or API keys. `.gitignore` covers the usual paths; tests must build their own synthetic inputs.
- **Text integrity is the core promise.** Changes to `inject.py`, `native_*.py`, `extract.py` or `verify.py` need tests showing native books stay byte-identical outside `<!--illus:start-->…<!--illus:end-->` blocks.
- **Keep the default path dependency-light.** The default image search must keep working with Python + Pillow/lxml/certifi and network only: no browser, Node, login or API key.
- **Real images only**, and never present an unverified identity as fact.
- Keep `README.md` and `README.zh-CN.md` in sync, and update `skills/book-illustrator/SKILL.md` when script behaviour or options change.

## Demo assets

`docs/assets/` and `examples/` hold the README demos. Their book excerpts and photos have their own rights, recorded in `examples/README.md`; they are not covered by the MIT license.
